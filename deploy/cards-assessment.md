# 卡牌与历史考核

本次功能对应 #11（积分与抽卡）；部署衔接参考 #10。提交或合并代码不等同于新功能已经在生产完成验收。

## 玩法与数据边界

- 共 21 种卡牌。图鉴按账号解锁，未抽到或获赠的卡牌显示灰色问号；库存和已发现记录分开保存。
- 每周前两次普通抽卡免费，之后先消耗额外抽取机会，再按每次 60 积分扣除抽卡余额。每周没有普通抽卡次数上限。
- 基础概率为 N 60%、R 28%、SR 10%、SSR 2%；普通抽卡参与 10 抽 SR+、50 抽 SSR 保底。仅触发 50 抽 SSR 硬保底时，有 30% 概率播放“捕获明光”并获得两张独立随机 SSR，允许重复；其余保底金光获得一张。自然抽中 SSR 获得一张，随机换卡不参与保底。
- 有效考勤每满一分钟产生一抽卡积分；新生成的正向娱乐加成也可产生积分。偷取、转移和连环同步不重复铸造积分。原有 `/points/me` 考勤账本继续保留，抽卡余额由独立玩法状态管理。
- 每周清零抽卡积分、免费次数使用量、额外抽取机会、娱乐时长及临时效果；库存、图鉴和保底跨周保留。界面展示对应提示。
- 娱乐时长允许为负，综合时长为 `max(0, 原始有效打卡 + 管理员调整) + 娱乐时长`。卡牌不改写原始考勤和原始积分，退出登录及通知断连也不代替签退，保留五小时作废规则。
- 抽卡、使用、赠送由服务端判定并保存幂等回执；动画在收到结果后播放，跳过或播放失败不会再次扣费。

## 考核与换届

成员统计展示综合时长、灰色“本周未完成”／绿色“本周已完成”状态及历史未通过次数。数据不足以判断时显示灰色“本周待核实”，不等同于未完成或失败，不增加历史失败次数。点击次数查看已结算失败周的周日日期。仅最新实际入学年级及上一届显示考核标记；高年级不展示标记，历史记录仍保留。年级来源为已进入打卡团队的业务成员，并非 SSO 中尚未获准进入的注册用户。

出现新一届成员后推进考核范围，不按九月或服务器年份切换。已观测的最高年级按周保留证据，不因新届成员退出而回退。开放周可随换届使旧届豁免，已结算终态不自动重算。考核目标沿用现有时长目标函数，本次不另改目标值。

入学年级须为 2000 至北京时间当前年份加一之间的整数；该范围只用于阻止明显录入错误，不自动产生新届。历史周按该周所在年份校验。现有成员或已保存年级证据异常时，该团队观察停止并明确报错，其他团队继续处理；须经数据核对和审计后纠正，不能自动清除年级记录或重算已结算历史。停用成员的真实年级证据继续保留。

所有周界线按 `Asia/Shanghai`：周一零点开始，周结束五小时后才允许结算，即下一周周一 05:00 起，详情展示的是前一周的周日。首次观察登记当周免考，观察到停用则当周豁免，不追罚启用前的周。观察断档、名单或数据读取不完整时保持待核实，不能按零时长判失败。

详见 [考核模块说明](../apps/api/src/modules/assessment/README.md)。

## 发布前置条件

沿用 [现有 Jenkins 流水线](jenkins/README.md)：PR 运行检查，生产流水线只跟踪上游 `main`。本功能涉及 API、Web 和 shared，合并后会进入两个服务的构建与部署范围。发布器只替换镜像，不会自动增加以下环境变量、挂载或数据库配置，必须先准备并核对。

### 私有卡面

21 张完整 PNG 不放入 Web public 或 Git 仓库。由发布管理员单独准备可信素材，并校验数量、文件名和哈希；文件名须与 `apps/api/src/modules/cards/card-catalog.ts` 中的卡牌 ID 对应，例如 `n-acceleration.png`。

将素材目录只读挂载到 API，并通过 `LEC_CARD_ASSETS_DIR` 指向容器内该目录。例如容器内使用 `/srv/lecpunch-assets/cards/<version>`。运行用户须有目录遍历和文件读取权限。未配置目录时卡面读取返回不可用，不应以开放静态目录绕过团队及解锁检查。

四段抽卡视频随 Web 镜像构建，位于 `apps/web/public/media/card-draw/`；N/R 对应蓝光，SR 紫光，SSR 金光或硬保底捕获明光。

### 考核起算

`ASSESSMENT_START_WEEK` 留空关闭观察任务；启用时必须填写北京时间周一的 `yyyy-MM-dd`，错误值拒绝启动。这仅控制历史考核观察，并非卡牌总开关。首次登记当周仍免考，不能将配置起算周理解为已经生成失败记录。

### 数据库与发布顺序

1. 备份 MongoDB，并保留当前镜像摘要和运行配置；记录备份时间及是否具备一致性保证。
2. 核对私有素材只读挂载、目录权限和起算配置，保持现有 SSO、网络策略、端口及数据库连接配置。
3. 预检成员年级、已保存年级证据及新集合，确认以下唯一索引能够建立：`card_games(teamId)`、`card_action_receipts(teamId,receiptKey)`、`card_week_archives(teamId,userId,weekKey)`、`assessment_memberships(teamId,userId)`、`assessment_weeks(teamId,weekKey)`。回执另有 `(teamId,actorId,at,receiptKey)` 查询索引，历史周另有 `(teamId,weekKey)` 查询索引。Schema 已声明索引；不得在发现重复数据时直接删库或忽略索引错误。
4. 在 PR 检查通过并获审核后合并。流水线校验同一提交、构建对应镜像、备份并发布；发布后检查容器健康、已认证 API、素材读取及观察任务状态。

当前版本没有自动生成历史失败记录的回填脚本。回滚旧镜像时保留新增集合及素材，不将回滚等同于撤销已发生的抽卡或考核；旧版本不会继续记录新增娱乐时长及考核结果。若发布期间已有玩法写入，须单独评估后续向前恢复和观察缺口，不能直接恢复旧备份覆盖新数据。

### 回执与周历史归档

新回执保存在独立集合，不设 TTL；仍通过认证并具有卡牌访问资格的启用成员，使用原操作编号长期重放可返回原结果。成员被停用或失去访问资格后，请求继续被拒绝，回执仍保留，不因回执存在绕过成员资格校验；恢复资格后可按原编号重试。操作列表按团队、成员和时间索引读取最近 20 条。已关闭五小时且完成加速核对的周状态保存到独立历史集合，综合时长与考核查询合并读取历史和当前状态。库存、图鉴及保底仍在团队当前状态中。

状态 CAS 与一个有界 `pendingWrite` 待办同时写入团队文档。将回执及周历史幂等写入目标集合后，才以 revision CAS 清除待办；未清除前禁止下一笔状态写入。进程在任一步中断后，后续请求会重试归档；不可写入时返回错误，不能将未归档历史当成零。该链路可运行于单节点 Mongo，无需为本 PR 改造生产数据库为副本集。

兼容旧的内嵌回执：每次加载最多迁移 100 条，先确认独立副本，再以 CAS 删除旧副本，迁移期间仍合并查询和重放。已确认副本发生内容冲突时停止，不覆盖原记录。历史迁移和回执都不直接删除，磁盘容量须持续监控。启用归档后不能直接回滚到只读取内嵌记录的早期卡牌版本，否则旧界面会漏读归档历史；应优先向前修复，并保留待办及两个归档集合。

## 当前限制

- 回执和已关闭周不再无限积累于团队文档。当前成员状态及单次归档待办仍受 8 MiB 防线保护；极端大团队达到此边界时停止写入，不能靠删除幂等记录腾空间。归档集合没有自动删除策略，仍需监控磁盘容量。
- 考核按本模块实际观察记录参与时间；未接入 SSO 的完整成员变更事件，无法还原两次观察之间短暂发生的入退组或停用。
- 已结算历史的人工纠错、删除后重建账号的历史归属，以及请假豁免尚未实现，不能通过直接改写终态代替审计流程。
- 本地自动化检查不代表生产镜像、SSO 真实登录和发布后观察已经完成验证。生产发布以流水线及实际运行证据为准。

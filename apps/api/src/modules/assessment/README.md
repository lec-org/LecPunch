# 独立历史考核模块（默认关闭）

此模块只新增自己的观察、登记与结算集合，读取现有用户、打卡、管理员调整及卡牌历史，不改写这些原始数据。

`ASSESSMENT_START_WEEK` 留空时关闭观察任务，不写参与登记或周快照。合法值必须是北京时间周一 `yyyy-MM-dd`，非法值明确拒绝启动，不能默默启用。用户已确认从本周开始，本地测试环境配置为 `2026-10-26`；此配置不代表生产环境已启用。

确认启用后，首次观察到 active 用户的时刻才记录到 `assessment_memberships.registeredAt`。这是本模块真实的“考核参与登记”时间，不是推测的 SSO 入组时间；账号创建时间也不能替代它。首次登记当周免考，因此配置启用周也不会立即追罚旧成员，最早下一个完整周才可能结算。

每个团队、每周单独快照：目标与成员年级在期初记录；每分钟观察完整名册，间隔超过五分钟、首见过晚或缺失期末覆盖时，结果保持待核实。停用在本周被观察到则本周豁免。停机和读取失败不能制造“零时长失败”。不存在的历史周不会事后创建快照。

只有团队实际存在的最新入学年级及上一届需要考核，不按日期、月份或服务器年份换届。例如已有最高 2026 级时范围为 2026/2025；出现已加入打卡团队的 2027 级成员后才推进至 2027/2026。当前周记录 `requiredEnrollYears`，继承已观测的新届证据并单向推进，避免新届最后一位成员退出后回退。新届加入可使旧届在尚未结算的当前周豁免，已完成的历史终态不重写。旧的未结算快照缺少年级证据时保持待核实，不能猜测后新增失败记录。

周结束五小时之后，综合考核时长为 `max(0,原始有效打卡+管理员调整)+娱乐时长`；娱乐时长允许负数。只有 completed、合法秒数的打卡进入结算。完整读取成功且数据合法后，纯引擎才可生成固定 complete/failed/exempt 结果；终态不自动重算。

`assessment_weeks` 每 teamId/weekKey 唯一，revision CAS 防并发重复写；历史失败记录按稳定 userId 保存。只提供同团队 JWT 查询，不把详情公开给匿名或其他团队。历史详情仅列已结算失败周，游标分页。考核观察任务在销毁时清理计时器。

成员统计页通过 `GET /assessment/member-summaries` 一次读取当前认证团队的累计失败次数，按签名 memberKey 关联。读取失败或成员缺失时显示不可用／待核实，不补成零。点击次数后按需读取历史分页；`assessmentDate` 从已保存 weekKey 推导对应周日（北京时间），实际结算仍在周结束五小时之后。当前周灰／绿状态仅表示综合时长是否达到目标，不等同于最终历史结算结果。

跨周继承读取该团队截至目标周的全部已观测年级最高值，而非只读最新周；已创建的开放周也合并这一最高值，防止旧周晚写入新届证据后被漏掉。未来周被排除，闭周及已结算终态不按后续年级重算。

未来如果需要请假豁免、人工纠错或删除成员后的资格处理，须另行设计审计路径，不能通过改旧周终态补丁绕过证据。此前已完成本模块的小范围 Review；新增成员统计展示以对应测试为准，不代表经过新一轮 Review 或生产验收。
